# Planning Workflow

Use when the user says `/plan`, asks for an implementation plan, or requests a plan before coding.

Start with:

```text
Matched workflow: plan.
```

Restate requirements, identify assumptions, flag risks, and break work into phases with exact files when known.

For implementation plans, include:

- Requirements.
- Affected files or entry points.
- Implementation phases.
- Testing strategy.
- Risks and mitigations.
- Success criteria.

Wait for user confirmation before coding when the user explicitly asks for a plan or the work is complex, architectural, or ambiguous.
